# main-service — Backend Logic & API Specification

This document is the **source of truth** for the Rovno.dev FastAPI backend. An AI reading this should be able to replicate the exact business logic, authentication flows, and database structure.

## 1. Tech Stack & Conventions

- **Framework:** FastAPI
- **ORM:** SQLAlchemy 2.0
- **Migrations:** Alembic (auto-applied on container start via Dockerfile `CMD`).
- **Database:** PostgreSQL
- **Cache / Queue:** Valkey (Redis-compatible) for OTPs and rate limits.
- **Pydantic v2:** Strict typing for all requests and responses. 
- **Errors:** Always return `HTTPException` with a `{"detail": "..."}` JSON body. 
- **Slugs:** Always use the `slugify` function from `app.shared.slugify` (transliterates Cyrillic to ASCII).

## 2. Core Logic & Business Rules

### 2.1 Authentication & Sessions
- **Registration:** User registers with `email` and `password`. Password must be 8+ chars, have 1 digit, and 1 uppercase letter. A 6-digit OTP is emailed. The user starts as `pending_verification`.
- **Username Generation:** On registration, the username is auto-generated by taking the email prefix, stripping non-alphanumeric chars, and appending a **random 5-digit number** (e.g., `elonmusk@x.com` -> `elonmusk84920`). Guaranteed unique.
- **Login:** Validates email + password. If 2FA is enabled, returns a `401 "2FA code required"`.
- **2FA (TOTP):** Users can call `/2fa/setup` to get a TOTP secret and QR URI. `/2fa/enable` verifies a 6-digit code and sets `totp_enabled = True`.
- **Sessions:** On successful login, a `UserSession` row is created (tracking IP, User-Agent). The JWT access and refresh tokens include the session `sid`. Users can view and revoke sessions via `/me/sessions`.
- **Password Reset:** Unauthenticated users call `/forgot-password` (sends OTP). `/reset-password` verifies the OTP and updates the hash.
- **JWT Flow:** 
  - Access token: expires in 15 mins.
  - Refresh token: expires in 7 days.
  - Frontend stores both in cookies. If API returns 401, frontend calls `/refresh` with the refresh token to get a new access token.

### 2.2 Content Creation (Articles, Projects, Events)
- **Slug Generation Logic:** When creating or updating any content, the backend generates a slug from the title. If the slug already exists in the database, it appends a **random 5-digit number** (e.g., `my-post-74839`) to prevent collisions.
- **ZIP Import (Articles):** Admin or authorized users can upload a ZIP. It can contain 1 or more folders. Each folder must have a `data.json` and a `media/` directory.
  - The backend reads `data.json` for title, MDX, tags, etc.
  - It saves all files in `media/` to the server.
  - It automatically replaces relative paths in the MDX (e.g., `./media/photo.jpg`) with the real public URLs.
  - **Imported articles are ALWAYS saved as `draft`.**
- **Review Workflow:**
  - Users with `can_create_articles` or `admin` can draft/publish.
  - Standard users can only publish if they are active Team Members. Otherwise, publishing sets status to `pending_review`.
  - Admins can bulk approve, reject, or delete.

### 2.3 Orders & CRM Integration
- **Order Creation:** Public endpoint. Accepts multipart form data (services array, user info, files).
- **Validation:** Phone numbers are validated via `phonenumbers` library and restricted to specific regions (RU, CIS, US, EU).
- **Lookup:** Finds or creates a `Client`. Finds or creates a `Company` (if `company_name` provided).
- **Notification:** Triggers an async background task to send email and Telegram messages to configured recipients.
- **CRM Sync:** Pushes the lead to a Twenty CRM instance (via REST API proxy).

## 3. API Endpoints

Base prefix: `/api/v1`

### 3.1 Auth & Me
- `POST /register/email` - Register user, send OTP.
- `POST /verify-email` - Verify OTP, return JWT.
- `POST /login/email` - Login (checks password, 2FA).
- `POST /refresh` - Refresh access token.
- `POST /forgot-password` - Send reset OTP.
- `POST /reset-password` - Apply new password.
- `POST /2fa/setup` - Generate secret.
- `POST /2fa/enable` - Enable 2FA.
- `GET /me` - Current profile.
- `PATCH /me` - Update profile (name, bio, team info).
- `GET /me/sessions` - List active sessions.
- `DELETE /me/sessions/{id}` - Revoke session.

### 3.2 Public Content
- `GET /projects` - Published projects.
- `GET /projects/{slug}` - Project detail.
- `GET /articles` - Published articles.
- `GET /articles/{slug}` - Article detail.
- `GET /events` - Published events.
- `GET /events/{slug}` - Event detail.
- `POST /events/{slug}/register` - Event registration.
- `GET /team` - List active team members.
- `GET /companies` - List companies.

### 3.3 Orders
- `POST /orders/create` - Public submission.
- `GET /orders/files/{filename}` - Serve uploaded order files.

### 3.4 Admin: Content
- `GET /admin/dashboard` - Stats.
- `GET /admin/users`, `PATCH /admin/users/{id}` - User management.
- `POST /admin/articles/import-zip` - ZIP import.
- `POST /admin/articles/bulk/{action}` - Bulk approve/reject/delete.
- `GET/POST/PATCH/DELETE /admin/projects` - Project CRUD.
- `GET/POST/PATCH/DELETE /admin/events` - Event CRUD.
- `PATCH /admin/events/requests/{id}` - Approve/decline event registrations.

### 3.5 Admin: CRM & Settings
- `GET /admin/order-requests` - List orders.
- `PATCH /admin/order-requests/{id}` - Update status.
- `GET/PUT /admin/notification-settings` - Order notification config (Root only).
- `GET /admin/catalog/{catalog}` - Unified taxonomy management (tags, categories, stack).

## 4. Environment Variables

| Var | Required | Purpose |
|---|---|---|
| `MAIN_DB_*` | Yes | Postgres connection. |
| `CACHE_*` | Yes | Redis/Valkey connection (OTPs, rate limit). |
| `JWT_SECRET_KEY` | Yes | Token signing. |
| `MAIL_SENDER` | Yes | SMTP email address. |
| `TELEGRAM_BOT_TOKEN` | Yes | Bot token for notifications. |
| `TWENTY_API_URL` | No | CRM API URL (if using Twenty CRM). |
| `TWENTY_API_KEY` | No | CRM API Key. |
